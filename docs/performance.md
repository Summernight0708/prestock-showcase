# 五节点流水线性能实验

## 优化过程

初期先构建串行原型，跑通财报处理流程，运行吞吐约 **12–16 份/分钟**。面对十万量级的数据规模，围绕并行化与流水线设计推进重构：

1. 将处理流程拆分为五个独立节点，让不同处理环节并行推进。
2. 抽象可复用的 Node 与 BufferPool，通过节点间缓冲池交接任务。
3. 为每个节点配置多个 worker，结合缓冲池容量配置组织并发处理。
4. 使用固定本地 PDF 样本执行持续吞吐验收，测得平均 **59.57 份/分钟**。

串行原型的 12–16 份/分钟记录项目早期运行水平；下文详细列出五节点版本的固定样本实验条件与结果。

## 实验配置

| 项目 | 配置 |
| --- | --- |
| 输入 | 固定 2,000 份本地 PDF 的临时副本 |
| 工具环境 | Poppler 25.07 |
| A/B/C/D/E worker 数 | 2/6/2/4/4 |
| AB、BC 缓冲池容量 | 16 |
| CD、CE、DE 缓冲池容量 | 8 |
| 轮询间隔 | 0.25 秒 |
| 预热 / 正式测量 | 120 秒 / 1,800 秒 |
| 供给 / 目标速率 | 60 / 40 份每分钟 |

## 测量结果

正式测量窗口内，30 个完整分钟累计完成 1,787 次终结确认，平均 **59.5667 份/分钟**；每分钟完成数为 41–70，全部达到 40 份/分钟的目标。来源进入至终结确认的 P95 为 **33.79 秒**。

[性能摘要 JSON](../evidence/performance.json)保存了每分钟计数、时延分位数、最终核账及来源文件指纹。
