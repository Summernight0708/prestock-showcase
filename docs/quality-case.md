# 从报告筛除异常到质量改进方案

## 问题发现

在检查 Codex 的运行汇报时，我注意到大量报告被筛除，且近期报告的筛除更明显。随后抽取两份原始 PDF 进行比较，并要求 Codex 对照报告原文、解析产物和质量规则定位原因。

## 排查过程

围绕三个层次展开分析：

1. **解析入口**：检查报表标题如何启用解析，追踪正文、摘要及完整报表的不同处理路径。
2. **事实识别**：核对期间、合并口径、列角色和指标映射，区分事实总数与本期合并指标数。
3. **质量分类**：检查指标数量、营业收入、总资产和经营现金流锚点，以及报表标题对报告提交资格的影响。

## 主要发现

- 完整报表标题驱动的入口使摘要指标表成为提取覆盖的扩展重点。
- 部分报告已提取出候选事实，但因本期合并指标数量或关键锚点缺失，被报告级质量规则分流。
- 报告完整性、单条事实可信度和历史时点可用性需要分维度管理。

这些发现将最初的“报告筛除较多”拆解为解析入口、指标识别和质量分类三个具体问题。

## 我的决策与推进

我提出提高提取质量和数据利用率的目标，使用 Codex 辅助分析并细化技术方案，推动形成两项改进设计：

- **摘要指标表独立提取**：保留期间、单位、归母口径及原文位置，建立可追溯的候选事实。
- **事实与报告分层管理**：分别判断单条事实可信度和整份报告完整性，通过隔离保存和质量标签管理候选事实。

验证要求采用原有测试集，围绕相同样本检查解析结果和质量分类。

## 案例产出

形成了一套从运行汇报发现异常、抽样检查原文、分解筛除原因，到提出改进目标与验证要求的处理过程，并明确摘要提取和质量分层两项改进设计。
